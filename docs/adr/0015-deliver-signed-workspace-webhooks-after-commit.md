# Deliver signed Workspace webhooks after commit

Workspaces can subscribe Webhook Endpoints to Short Link events so automation tools can react to changes without polling. Short Link mutations record one Webhook Delivery per subscribed, enabled endpoint inside the same database transaction as the mutation, and the delivery job is queued only after that transaction commits. A rolled-back mutation therefore leaves neither a delivery row nor a queued job, while a committed mutation never depends on the receiver being reachable. Each delivery stores the exact JSON body it sends, so every retry reuses the same Webhook Event identifier and the same signed bytes.

Delivery is at least once. Receivers deduplicate on the event identifier and verify an HMAC-SHA256 signature over `{timestamp}.{raw body}` with a replay tolerance window. Attempts are bounded, use exponential backoff, and run on the queue worker so a failing endpoint never slows down link edits or public redirects.

## Signing secrets and ADR 0002

ADR 0002 keeps infrastructure secrets, such as mail or OAuth credentials, out of product settings because they configure the whole installation and belong to deployment. A Signing Secret is different: it is an integration credential scoped to one Webhook Endpoint, generated by Openlink rather than entered by an administrator, and meaningless outside that endpoint. Storing it alongside the endpoint therefore does not contradict ADR 0002. It is encrypted at rest with the application key, shown only once when it is created or rotated, never returned by later reads, never included in payloads, and never written to job payloads or delivery history. Rotation keeps the previous secret, also encrypted, for a 24-hour overlap during which deliveries carry signatures from both secrets, so pending and retrying deliveries keep verifying while receivers deploy the new secret.

## Outbound request safety

Webhook Endpoint URLs must use HTTPS. Saving an endpoint checks only the URL itself, without DNS lookups, so a slow resolver cannot hold up the request. Before every attempt Openlink resolves the hostname, rejects the attempt if any resolved address is loopback, private, link-local, carrier-grade NAT, multicast, reserved, or otherwise not publicly routable (which covers cloud metadata addresses), and pins the connection to the validated address so DNS rebinding cannot swap the target between check and connect. Redirects are never followed; a redirect response is recorded as a failed attempt. TLS certificate verification stays enabled, and the response body is capped at 64 KB.

## Considered options

- **Model events and dispatch from listeners after the response.** Rejected because events fired outside the transaction can describe changes that were later rolled back, and dispatching without a persisted record makes explicit retries and delivery history impossible.
- **Follow redirects after re-validating each hop.** Rejected for the MVP: a receiver that redirects a signed POST is misconfigured, and refusing redirects removes a whole class of SSRF bypasses.
- **Send every visit and scan.** Deferred. Visit volume would dominate the queue and visits carry visitor data that webhook payloads must not expose.
